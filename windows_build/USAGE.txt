Folder Review 0.14.0 - Windows x86-64

Copy this folder to a writable local folder on the Windows computer.
Double-click folder-review.exe to open the desktop window. Browse for a folder
or paste its path, choose the report path, and click Create Excel report.
Progress, COMPLETE/PARTIAL status and Open report folder stay in the window.
Auto/manual workers and advanced metadata use the same scanner as the CLI.
Use --cli for the terminal folder prompt; --gui alone opens the window.
Local folders, mapped drives, and UNC paths are supported.

For command-line use:
  folder-review.exe --root "C:\Data" --output "C:\Reports\folder-review.xlsx"

The output folder must already exist. Without --output, folder-review.xlsx is
saved beside the EXE. The EXE and report may be inside the target. The selected
report is excluded on every scan. Reports may be local or on SMB; existing
reports are atomically replaced. Other input files remain protected. Only the
report and its staging file may be written there; the parent directory timestamp
changes. Runtime and processing workspaces remain local outside the target.
Paste a quoted/unquoted folder path with Ctrl+V or Shift+Insert, then press Enter.

Workers default to auto: CPU-based, up to 16 local or 32 network workers.
Use --workers 1..64 to override; auto is a bounded heuristic, not a guarantee
of optimal performance for every disk or server.
All column widths are 5 character units; inventory rows 1-6 freeze at A7.
dax_reference!A1 contains the DAX frequency-list measure as literal text.
Copy its text from the formula bar and edit the first SELECTCOLUMNS line.

Scanning does not access external web services or download dependencies.
SMB inputs remain supported; reads use operating-system file-sharing traffic.
Input is read-only except the selected report and its atomic-save staging file.
Archive/XLSX processing work files stay local outside input.
OS access-time updates, cloud hydration and antivirus are outside app control.
The EXE initially unpacks to OS temp; input containing that runtime is rejected.

The default workbook omits advanced filesystem metadata and the raw suffix,
retaining Hidden and all content/inspection columns. Add --full-metadata for all columns.
Actual inspected file paths/names remain in the workbook. Keep reports private.

Duplicate group IDs start at 1, only for repeated fully read contents.
Unique, virtual and unhashed rows have blank IDs.
For duplicate pivots: exclude blank IDs, group by Duplicate group, sum last.
IDs belong to this report only. Internal BLAKE3-256 uses native code and reusable
read buffers; full-file hashing increases disk/SMB traffic. Unreadable/changing
content and links have no ID; this is not a filesystem snapshot.
Raw BLAKE3 is available with --full-metadata.

last is ALWAYS 1. Filter Virtual row and Inspection state to select rows for analysis.
Virtual markers: dummy.dummy (no inventoried files), deny.deny (access denied),
password.password, corrupt.corrupt, limit.limit and error.error. No file is
created. Original locations remain in hierarchy/full paths; errors and known
sizes remain visible. Virtual rows have no content ID or extension.
File type group and subgroup provide two levels above the extension, using
fixed common categories. Content recognition remains a separate column.
Recognizable version/cache suffixes are filtered; --full-metadata keeps the raw suffix.

Review the scan_status worksheet:
  Exit 0: COMPLETE inventory.
  Exit 2: PARTIAL inventory; review the recorded errors and limits.
  Exit 1: fatal failure.

Python, uv, and 7-Zip do not need to be installed.

Only .zip, .rar and .7z filenames with recognized archive content are expanded.
Other files remain single rows, including Visio, Office, OpenDocument, EPUB,
application/install packages and unknown ZIP-based file formats. This applies
inside archives too. A raw archive renamed to .bin is intentionally a leaf.
Recognized document packages renamed to .zip remain leaves as well.

python/ contains the matching Python delivery of this same scanner.
